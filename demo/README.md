# PITFALL — демо

Проверка корректности признаков по времени **дифференциальным исполнением**.

```
φ(D, t) = φ(D|t, t),   D|t = { r ∈ D : avail(r) ≤ t }
```

Программа признаков вызывается дважды: на полной базе и на базе, физически усечённой
на момент предсказания. Расхождение выходов — **доказательство** нарушения, а не подозрение.
Ни код, ни SQL не разбираются: программа — чёрный ящик. Ложных срабатываний нет по построению.

## Интерактивная страница (то, что показываем на стенде)

`demo/index.html` — самодостаточная страница (открывается офлайн, шрифты с Google Fonts при
наличии сети, иначе системные). Семь разделов: реальный продавец с перетаскиваемой датой
(«что видит наивный признак» против «что было известно»); переключатель программ × моментов
с вердиктом, объяснением и выходами бок о бок; игра «обмани проверку» (8 функций);
ползунок сдвига отсечки; порог промышленной проверки на диаграмме; локализация по каналам;
границы метода.

```bash
python3 build_site_data.py   # ~1.5 мин: все числа считаются на реальной базе → site_data.json
python3 build_site.py        # вшивает данные в site_template.html → index.html
```

## Сценарий у стенда (три акта, ~1 минута)

Тот же порядок, что в разделе Demonstration статьи и на постере.

1. **Поймай баг (20 с).** Раздел 1: один продавец, ползунок даты. Наивный средний отзыв
   и то, что было известно на дату, расходятся (на 1 апреля 2018: 3.40★ против 4.50★);
   звёзды, написанные после даты, краснеют. Вывод: заказ уже был, отзыва ещё не было.
2. **Почему не посмотреть просто на признак (20 с).** Раздел 3 «Guess the peek»: восемь
   функций, посетитель говорит, какие подглядывают, проверка отвечает. Средний отзыв
   кажется безопасным и не является им; z-score цены подглядывает вообще без соединения.
   Затем карточка вердикта раздела 2: промышленная проба даёт 0.69 на задаче B и молчит
   на обоих порогах, а проверка говорит «нарушение» и модель получает +5.3 п.п.
3. **Где именно утекло (20 с).** Раздел 6: каналы отключаются по одному, двигаются два
   столбца отзывов и два столбца доставки, остальное нет. Инструмент локализует;
   починка — две строки («our code, fixed»).

Экспертный SQL, rel-event, LLM-доли, гранулярность таймстемпов (раздел 7) — только если
спросят.

## Консольный прогон

```bash
python3 demo.py            # четыре сцены, всё считается вживую, ~2 минуты на 2 ядрах CPU
python3 demo.py 2          # одна сцена (4 — LOCATOR)
python3 demo.py --lang ru  # русские подписи (по умолчанию английские; также PITFALL_LANG=ru)
python3 demo.py --no-color # без ANSI, для записи в лог
python3 demo.py --program try_me.py [--task seller|product]
                           # «обмани оракула»: проверить и локализовать СВОЮ функцию признаков
                           # сигнатура features(db, seed_time, entities) -> DataFrame; см. try_me.py
```

Зависимости — `../requirements.txt` (см. корневой README, окружение `../.venv`). Данные — Olist
в `../PITFALL_olist_data/` (7 таблиц, 112 650 позиций заказов, 2016-09 — 2018-10), другой
каталог — через переменную `PITFALL_DATA`.

## Четыре сцены

| | что | оракул | промышленная проверка | завышение |
|---|---|---|---|---|
| 1 | featuretools с настройками по умолчанию (`ft.dfs` без таблицы моментов) | **УТЕЧКА**, 11 колонок | DataRobot **пропуск**, H2O уведомление 2/3 (0.809) | **+14.8…+16.3 п.п.** |
| 2 | наш собственный эталон, первая версия | **УТЕЧКА**, 4 колонки | **пропуск** у обеих (0.687) | **+3.1…+5.3 п.п.** |
| 3 | тот же эталон после исправления | ЧИСТО | верно молчит | 0.00 |
| 4 | LOCATOR: усечение по одному каналу за раз на программах сцен 1–2 | сцена 2 → `flat.review_score`, `flat.late`, `flat.delay_days`; сцена 1 → `items` (строки после t) | — | патч (усечь вход только по найденным каналам) → ЧИСТО |

Сцена 1 — поведение популярной библиотеки по умолчанию, а не наша симуляция.
Сцена 2 — ошибка, найденная оракулом в коде авторов самого оракула.
Сцена 3 — отрицательный контроль: без него первые две ничего не стоят.
Сцена 4 — локализация тем же приёмом: столько вызовов программы, сколько каналов доступности
(появление строки таблицы / позднее значение колонки); канал, на котором выход меняется, — путь
утечки. Патч не трогает код: `masked_program(program, channels)` усекает вход по найденным каналам.

## Границы метода

- **Изменяемое поле без истории непроверяемо.** У `order_status` нет метки времени; усечённая
  база для такой колонки неотличима от полной. Признак `canceled` исключён из всех режимов.
- **Недетерминированная программа** даёт расхождение без утечки — нужен фиксированный seed.
- **Пропуски возможны:** утечка, не проявившаяся на конкретном моменте `t`, на нём не видна.
  Ложных срабатываний при этом нет — асимметрия сознательная.
- Одна база, три задачи, три момента предсказания. Предварительный результат.

## Ошибка, найденная отрицательным контролем

В первой версии оракула `frames_equal(None, None)` возвращал `False`: программа, забывшая
`return`, детерминированно давала `None` на обоих вызовах и получала вердикт УТЕЧКА.
Баг найден отрицательным контролем **до** основного эксперимента; переаудит 23 вердиктов
показал 1 ложный. В `pitfall.py` этот случай обрабатывается явно.
