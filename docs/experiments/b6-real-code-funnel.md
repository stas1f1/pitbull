# B6 — воронка реального feature-кода

Статус: вычислительное ядро завершено; ручной timing-критерий нарушен.

## Вопрос и протокол

Можно ли подключать публичный relational feature-код к интерфейсу
`get_features(db, entity_ids, seed_time)` без переписывания его feature-логики?
До поиска были зафиксированы критерии включения, предел 30 просмотренных
кандидатов и запрет заменять неудобный выбранный файл после ошибки. Полный
протокол находится в `b6-real-code-protocol.md`.

Wrapper может параметризовать ввод-вывод и компилировать dbt/Jinja в локальный
SQL, но не добавляет или удаляет признаки и временные фильтры. Если исходный
файл не использует cutoff, адаптер также не изобретает cutoff: B6 измеряет
подключаемость к харнессу, а не объявляет такой код point-in-time корректным.

## Воронка

Просмотрено 30 файлов из публичных репозиториев. Десять файлов из трёх
MIT-проектов прошли критерии: пять Python и пять SQL. Двадцать исключены.
Первые шесть исключений включали:

- два — без лицензии;
- один — без multi-table join;
- один — только загружает данные и не строит признаки;
- один — работает с одной плоской таблицей;
- один — notebook-only.

Ещё 14 файлов были просмотрены для C4 после заполнения исходной квоты B6.
Они не заменяют выбранные файлы: четыре staging-модели не содержали
multi-table feature construction, snapshot и восемь служебных/обучающих
файлов не строили relational features, ещё один SQL-репозиторий не имел
лицензии.

Реестр с URL на закреплённые commit SHA, основаниями исключения и путями
адаптеров: `pilot/b6_candidates.csv`.

## Выполнение

Повторный локальный smoke-call успешен для 9/10 адаптеров. Успешно выполнены
четыре Python-файла Home Credit и пять dbt SQL-моделей Olist. Десятый файл —
AWS Glue/Spark ETL — остановился на `ModuleNotFoundError: awsglue`. В
соответствии с протоколом он сохранён в знаменателе и не заменён более удобным
файлом. Суммарное машинное время десяти smoke-call составило 7.05 с в
последнем воспроизведении.

Проверки используют минимальные локальные таблицы. Они подтверждают
интеграцию и исполнимость пути, но не заменяют воспроизведение исходных
production-окружений или проверку на полных исходных наборах данных.

## Отклонение и вердикт

Поле `wrap_minutes` должно было измеряться вручную от начала адаптации каждого
файла. Stopwatch не был запущен до работы, а подмена этого значения временем
исполнения создала бы ложную метрику. Поэтому минуты оставлены пустыми;
`pilot/b6_results.json` явно содержит `timing_protocol_satisfied=false`.

**Neutral.** Результат показывает техническую подключаемость 9/10 выбранных
файлов и обнаруживает реальную инфраструктурную границу AWS Glue. Однако он не
даёт заранее обещанной оценки человеческой стоимости адаптации. Для строгого
закрытия ценовой части B6 нужен новый независимо засечённый проход адаптации;
текущие адаптеры нельзя ретроспективно использовать для этой метрики.
