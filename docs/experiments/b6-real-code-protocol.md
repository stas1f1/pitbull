# B6 — протокол выборки реального feature-кода

Статус: протокол зафиксирован до отбора файлов.

## Единица выборки

Один публичный Python- или SQL-файл, который строит признаки из нескольких
таблиц и содержит явную временную ось. EDA-only ноутбуки, готовые плоские
матрицы признаков, синтетические примеры и код без лицензии исключаются.

## Фиксированная воронка

1. Найти кандидата публичным поиском по заранее заданным запросам.
2. Зафиксировать URL, commit SHA, лицензию, язык и причину включения.
3. Проверить наличие join/merge, временной колонки и вычисления признаков.
4. Извлечь один самодостаточный файл без изменения feature-логики.
5. Обернуть его в интерфейс `get_features(db, entity_ids, seed_time)` либо
   параметризованный SQL. Обёртка может переставлять вызовы и передавать cutoff,
   но не может добавлять или удалять признаки и временные фильтры.
6. Засечь ручное время от начала адаптации до первого исполнимого вызова.
7. Сохранить исход ошибки либо вердикт, не заменяя неудобный файл следующим.

Основной знаменатель — первые десять кандидатов, прошедших шаги 1–3. Воронка
показывает также все исключения до этого момента. Верхняя граница поиска —
30 просмотренных кандидатов; после неё B6 фиксируется как неполный, если десять
подходящих файлов не набраны.

## Поля реестра

`candidate_id`, `source_url`, `commit_sha`, `license`, `language`,
`retrieved_at`, `temporal_axis`, `relations`, `selection_status`,
`exclusion_reason`, `wrapper_path`, `wrap_minutes`, `execution_status`.
