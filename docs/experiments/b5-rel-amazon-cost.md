# B5 — стоимость rel-amazon

## Вопрос

Сколько машинного времени занимает differential execution на самом крупном
наборе Tier B?

## Данные и воспроизведение

Используется закреплённый полный прогон `rel/out/sql_oracle_amazon.csv`:
четыре экспертные SQL-программы, для каждой три проверки детерминированности,
один negative control и три основных prediction time. Сводка воспроизводится:

```text
python pilot/b5_score.py
```

Большие parquet читались DuckDB потоково; полная таблица review не загружалась
в pandas. Текущий шаг повторно обрабатывает сохранённые измерения, а не выдаёт
их за новый прогон на текущем компьютере.

## Результат

| Программа | Все фазы | Main checks |
|---|---:|---:|
| amazon_item-churn.sql | 105.7 с | 34.2 с |
| amazon_item-ltv.sql | 115.5 с | 41.0 с |
| amazon_user-churn.sql | 72.1 с | 26.5 с |
| amazon_user-ltv.sql | 137.0 с | 55.6 с |
| **Всего** | **430.3 с** | **157.3 с** |

Всего выполнено 28 запусков, включая 12 main-проверок; `ERROR=0`. LLM API не
использовался. B5 закрывает недостающую строку таблицы машинного времени A5,
но абсолютное время относится к машине исходного закреплённого прогона.
